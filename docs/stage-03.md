# 3단계 — 가능 시간 투표, 합주 확정, 참석 응답

## 만든 것

| 기능 | API | 화면 |
| --- | --- | --- |
| 주간 가능 시간 보기 | `GET /api/bands/{id}/availability?week=YYYY-MM-DD` | 가능 시간 투표 |
| 내 가능 시간 저장 | `PUT /api/bands/{id}/availability` | 가능 시간 투표 |
| 합주 목록 (예정·지난) | `GET /api/bands/{id}/jams` | 밴드 상세 → 합주 |
| 합주 확정 (방장) | `POST /api/bands/{id}/jams` | 투표 → "이 시간으로 확정" |
| 합주 상세 | `GET /api/jams/{id}` | 합주 상세 |
| 시간·장소 변경 / 취소 (방장) | `PATCH /api/jams/{id}`, `POST /api/jams/{id}/cancel` | 합주 상세 |
| 참석 응답 | `PUT /api/jams/{id}/rsvp` | 합주 상세 |
| 다음 합주 | `/api/me/bands`, `/api/bands/{id}`의 `nextJam` | 내 밴드 카드, 밴드 상세 |

### 테이블

```
availabilities  id, band_id, user_id, week_start(월요일), slot      (band,user,week,slot 유니크)
jams            id, band_id, starts_at(UTC), duration_minutes, place, memo, status, created_by, created_at
jam_rsvps       id, jam_id, user_id, answer(YES/LATE/NO), updated_at  (jam,user 유니크)
```

## 왜 이렇게 만들었나

### 1. 시간은 UTC로 저장, 달력 판단은 한국 시간
- `starts_at`은 `Instant`(UTC). API는 `2026-11-27T20:00:00+09:00`처럼 오프셋을 붙여 주고받는다.
- "이번 주가 언제부터인가", "금요일 20시"처럼 달력이 필요한 판단만 `Asia/Seoul`로 한다.
  일요일 밤 11시 반(한국)은 UTC로는 일요일 오후라서, 서버가 UTC로 주를 자르면 하루가 밀린다.
- 프론트도 같은 기준으로 계산한다 (`lib/time.ts`, 경계 시각 테스트 포함).

### 2. 가능 시간은 "칸" 하나가 한 행
- `slot = 요일 × 24 + 시` — 월요일 20시는 20, 금요일 20시는 116.
- 한 사람의 한 주 선택을 JSON 한 칸에 넣지 않은 이유: 칸별 인원 집계·"누가 가능한지"를 DB에서 바로 셀 수 있고,
  나중에 "이번 주 투표 안 한 사람에게 알림" 같은 기능이 쿼리 한 줄이 된다.
- 저장은 보낸 목록으로 통째로 바꾸지만, 실제로는 **빠진 칸만 지우고 새 칸만 넣는다.**
  Hibernate는 한 트랜잭션 안에서 INSERT를 DELETE보다 먼저 내보내기 때문에, "다 지우고 다시 넣기"를 하면
  그대로 남는 칸이 유니크 키에 걸린다. (흔한 함정이라 주석으로도 남겨 둠)

### 3. 시간을 옮기면 참석 응답을 비운다
- "금요일 8시 참석"이라고 답한 사람이 "토요일 2시"에도 오는 건 아니다.
- 시작 시각이 바뀌면 응답을 지우고 다시 받는다. 장소·메모만 바뀌면 그대로 둔다.
- 방장은 확정·변경과 동시에 참석으로 들어간다.

### 4. "지금"을 주입한다 (`Clock` 빈)
- 지난 합주인지, 응답을 잠글지, 이번 주가 언제인지 모두 `clock.instant()`로 판단한다.
- 테스트에서는 `MutableClock`을 넣어 "이틀 뒤"로 돌린 다음, 지난 합주로 옮겨지는지·응답이 잠기는지 확인한다.
  `Instant.now()`를 코드 곳곳에서 부르면 이런 테스트는 실제로 이틀을 기다려야 한다.
- 기기 시계가 아니라 서버 시각이 기준이다. 휴대폰 시간을 바꿔도 지난 합주에 답할 수 없다.

### 5. 같은 합주·같은 밴드 쓰기는 행 잠금으로 줄 세우기
- 참석 응답은 합주 행, 가능 시간 저장과 합주 확정은 밴드 행을 잠근 뒤 처리한다 (2단계와 같은 방식).
- 같은 사람이 버튼을 빠르게 두 번 눌러도 응답이 두 줄 생기지 않고, 방장이 두 기기에서 같은 시간에 확정해도
  두 번째는 "그 시간에 이미 잡힌 합주가 있어요"를 받는다.

### 6. 나간 멤버는 세지 않는다
- 가능 시간·참석 집계는 항상 "지금 멤버" 기준. 나간 사람의 기록은 남지만 숫자에는 들어가지 않는다.
